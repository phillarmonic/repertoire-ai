## v1.12.1: a fresh clone gets the project's skills

Three fixes, all from running the documented path on a second machine.

### Fixed

- **A fresh clone reproduces a project set up with `repertoire --project add`.**
  That command writes the project's skills to the `requirements` section of
  `repertoire.yaml`, and `bootstrap` and `sync` used to read only `skills`.
  They saw an empty manifest, wrote the starter list over it, and then failed
  to find an agent to install into. Both commands now install `requirements`
  and restore a missing copy, so one command on a new laptop or in CI gives the
  same set the lock records.

- **`doctor` audits the copies inside the checkout.** A clone whose agent
  directories were never restored reported `no issues found` while
  `repertoire show <skill> --project` listed every target as `missing`. The new
  `project-skill-health` check resolves each declared target against the
  checkout and reports the ones that are absent, and `doctor --fix` reinstalls
  them.

- **The no-client error names a value you can type.** `repertoire add` without
  `--target` on a machine with no detected agent said `use --target`, which
  leaves the reader guessing. It now says
  `use --target <name> or --target all`, and the quickstart shows the
  `--project` form that writes a lock you can commit.

No flags, file formats, or manifest schema change.

Install on macOS, Linux or Windows:

```bash
curl -fsSL https://raw.githubusercontent.com/phillarmonic/repertoire-ai/master/install.sh | bash
```

Every asset ships with `checksums.txt`, and the installer verifies the digest
before it moves the binary into place.
